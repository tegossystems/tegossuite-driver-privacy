Information the App processes

  • Account and identity information: username, account or employee identifier, email address, name, organization/client identifier, role or permissions, and authentication credentials and tokens. Login details are used to authenticate you.
  • Driver and work records: tours, assigned jobs and stops, vehicle and inspection details, defect descriptions and notes, questionnaire answers, mileage, barcode values, work status, and related identifiers.
  • Location: latitude and longitude, and associated dates or times. The App can request foreground and background location access. See “Location access” below.
  • Images and signatures: photos captured for jobs or vehicle checks, names entered with signatures, and drawn signatures. Photos may be resized before being attached to a work record.
  • Device and service information: Android device identifier, Firebase account/device identifiers, push-notification token, App version and update information, network/request status, and technical diagnostic or error information.
  • Camera-scanned information: supported barcode or QR-code values when the scanning feature is used.

How information is used

Information is used to sign you in; provide assigned work; record tour, job, and vehicle-check activity; attach photos, signatures, and scanned values to work records; synchronize records when connectivity is available; maintain the session and device connection; deliver configured app updates and notifications; and diagnose service or app failures.

Location access

When you start a tour or save a vehicle check, the App requests the device’s current or last-known location and can send its coordinates and a timestamp with that work action to the organization’s configured service.

The App also contains a background-location task. When an account is active and notification and background-location permissions are granted, the App requests location updates and stores location coordinates with a timestamp on the device. The reviewed task does not itself send those periodic background samples to a server. Background location is also used by code intended for an arrival reminder; the reviewed arrival-detection and notification-scheduling logic is currently inactive. Your organization should confirm the production behavior and whether this feature is needed.

You can manage location permissions in Android settings. If you deny or revoke location access, location-dependent work features may not function fully.

Camera, microphone, and notifications

The camera is used to take work-related photos and scan barcodes or QR codes. The Android build requests camera access. The build configuration also requests microphone permission for camera functionality, but the reviewed application code does not show an audio-recording feature. The App requests notification permission for its arrival-reminder setup. Confirm the final Android permission list and remove permissions that are not required.

Where information is sent and who may receive it

  • Your organization’s configured service: receives account and work information submitted through the App, including relevant photos, signatures, scanned values, and location accompanying work actions. Your employer or business may make this information available to authorized personnel.
  • Firebase / Google services: depending on the release configuration, the App uses Firebase Authentication and Realtime Database for sign-in, synchronization, and connection status. Android code also obtains a Firebase Cloud Messaging token. Crash reporting and performance-monitoring code is present. Analytics code records screen and API activity. The Android manifest contains settings that disable Firebase Analytics and Performance collection, while application code also attempts to log events and enable performance collection. Actual transmission in the published build must be verified.
  • Google Maps: if the Maps feature is enabled by your organization, the App can send coordinates for reverse geocoding and can request maps using work addresses. This feature is disabled by the code’s default configuration, but configuration can change it.
  • Azure Blob Storage: an optional troubleshooting/export feature can upload diagnostic logs and queued API requests. Those records can contain request details and work or account information. The code selects Azure Blob Storage for this export path. The App also includes a Firebase Storage uploader, but the reviewed configuration does not select it as the active uploader.
  • Expo Updates: the App checks for and downloads application updates through its update service.

Storage and retention

The App stores information locally on the device to support authentication, offline work, and later synchronization. This can include access and refresh tokens, a remembered username, work records, photos or signatures attached to records, location samples, queued requests, and diagnostic logs. The App uses local persistent storage; the code does not establish that this storage is encrypted.

Signing out removes the locally stored authentication token and session-expiration value, but does not clear all local work records or the remembered username. A “Clear Local” option in the App removes the App’s local database and may delete work that has not synchronized. The Android application manifest permits application backup; whether App data is included depends on Android backup behavior and configuration.

The reviewed code does not define a general retention period for information held by the organization’s service, Firebase, or Azure. Local logs do not have a time-based deletion schedule. Queued requests have a configured 24-hour stale threshold, but cleanup occurs during retry processing, so this is not a guaranteed 24-hour deletion. The organization must specify and publish its actual retention schedule.

Deletion and privacy requests

The App provides sign-out, local-data clearing, and deletion of certain individual work records. These controls do not delete your account or guarantee deletion of information already synchronized to organizational or provider systems. No in-App account-deletion flow was identified in the reviewed code.

To request access, correction, or deletion of account or work information, contact your employer or business administrator and the privacy contact listed above. The responsible organization must confirm how requests are handled and any legal or operational retention exceptions.

Security

The App and its service providers use account and device identifiers to support the service. No security method can be guaranteed to be completely secure. The organization should review the App’s credential handling, local storage, diagnostic logging, cloud configuration, and access controls before publication.
